# Docker Workbench v0.1 实施与验收

开发期历史记录，自 2026-10-27 起，macOS / Apple Silicon。此记录区分自动化、桌面验收、真实服务器只读验证和其他平台待验收项。内部主机、账户与业务标识已移除；下列结果仅代表记录当时的验证，不代表当前 GitHub CI 已运行。

## 交付内容

正式源码：code/ui/、code/core/、code/src-tauri/。在 code/ 目录执行构建入口：pnpm desktop:dev / desktop:build。方案与操作说明已更新，早期离线模拟原型保留在 code/index.html。

本机交付包：code/releases/0.1.0/Docker Workbench.app、Docker Workbench_0.1.0_aarch64.dmg，以及 SHA256SUMS.txt。arm64 .app 约 17 MiB，DMG 约 7 MiB。使用本地 ad-hoc 签名，codesign --verify --deep --strict 通过；尚未 Developer ID 签名、公证或公开发布。

## macOS 原生界面验收

使用实际打包的 Tauri 程序，通过原生界面操作，没有使用 Playwright。隔离引擎仅提供进程内数据，未运行真实容器或真实 shell 命令。

- 添加 Unix Socket 连接，测试与保存，实际核心选择服务端 API 1.43。
- 读取 2 个容器和 Compose 分组、中文实时日志；切换容器，Inspect 取得对应 ID 与标签。
- Stats 收到 CPU 8.00%、内存 48 MiB 的受控样本。
- 默认只读时启停按钮禁用，终端说明要求读写；核心测试另验证后端拦截。
- 仅对隔离连接关闭只读，预览只包含选中的 worker，启动后从 1/2 回读为 2/2，并显示持久成功记录。
- xterm 打开、键盘输入 pwd，经核心通道返回 /acceptance-fixture。
- 切换 English，菜单、表单、状态、预览与操作记录同步切换；退出重开保留语言与连接。
- 最终安装包再次打开，确认应用与 Go 子进程从交付目录启动，真实主机可在桌面程序中直接只读连接。

## 真实服务器只读验证

使用经授权的 SSH 测试环境和本地私钥，以已有 known_hosts 严格验证连接。通过 Go 核心只调用版本 / 容器读取接口；公开记录不包含环境地址、账户或密钥路径。

测试环境返回 Docker 24.0.7、Linux arm64，服务端最高 API 1.43，核心自动使用 1.43。桌面成功读取容器并按 Compose 标签分组。没有启停、重建、删除、Compose 部署或进入真实服务器交互终端。

真实联调发现并修复 ANSI 控制码影响级别解析，以及禁用 Unix 转发时单一 SSH 连接的 exec 会话限制。补充受限 SSH 服务回归测试，在每连接最多 6 个会话下同时打开 20 路日志；核心通过受限连接池分配额外认证连接，未触发服务端会话拒绝。回退命令清理远端 Docker 环境并显式固定 socket。

真实主机复测订阅 21 个日志源、观察 8 秒，收到 20 个源共 60 条输出，警告为空，ANSI 控制码残留为 0，识别 INFO / WARN / ERROR；没有输出的源不据此推断异常。此短时验证不替代长期压测。

临时验收引擎结束后已停止，验收连接已清理；连接备份与本机应用数据不属于公开仓库，也未打进安装包。

## 尚需真实平台与发行验收

Windows/Linux 原生桌面包未在本机生成或安装；Named Pipe、系统凭据服务、文件选择和 WebView 差异仍需对应系统运行验证。当时已提供三平台本机架构构建和产物上传配置，但未执行远程流水线；后续实际运行结果请查看仓库 Actions。

尚未验证多级跳板、PPK、任意 ProxyCommand、原生 Windows 容器 shell；这些不在当前支持范围。HTTP/SOCKS 代理、加密私钥、SSH Agent、三系统系统凭据服务仍需真实环境组合补测。没有做 50,000 行长期高并发 / 弱网耐久压测。

正式商业签名、公证、自动更新、卸载升级验收未完成；需发行身份及原生运行环境。当前版本作为可运行的首版交付，不等同三系统正式发行已验收。
