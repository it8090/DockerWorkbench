# Docker Workbench 使用说明

对应源码版本 0.1.5。[返回项目首页](../README.md) · [English overview](../README.en.md)

## macOS 标题栏

0.1.2 起，标题栏压缩为 36px，仅保留工作空间、搜索、语言、主题和添加连接，与系统红绿灯位于同一行；移除 Logo、软件名称和版本号。拖动工作空间文字或标题栏空白处可移动窗口，双击可放大或恢复。红绿灯继续提供关闭、最小化与全屏操作，标题栏按钮保持正常点击。Windows/Linux 保留原有系统标题栏。

## 工作空间与连接配置

资源管理器上方的“当前工作空间”用于切换团队或项目范围，右侧齿轮打开管理窗口，可新建、重命名工作空间，并将已有连接移动到其他空间。首次升级时，原有连接自动归入“默认工作空间”。切换工作空间会保留 Docker 连接会话，资源树、对象标签、搜索和操作记录仅显示当前空间。空间及当前选择在重启后保留。

连接可在工作空间管理窗口直接移动，无需重新测试网络，也不修改已有凭据、Compose 关联或只读设置。只有空的自定义工作空间可以删除；默认空间始终保留。工作空间用于本机连接归类，不提供团队权限隔离。

左下角“连接与 SSH 配置”打开集中管理弹窗：左侧按工作空间列出已有连接，右侧编辑所选连接，底部固定显示状态及“关闭 / 应用 / 保存”按钮。“应用”保存并继续编辑，“保存”成功后关闭弹窗。左侧“新建连接”和右上角“添加连接”进入同一配置流程。未保存的修改在切换或关闭时提示确认。

## 第一次连接

右上角“添加连接”填写名称、环境和传输方式，点击“应用”或“保存”时自动测试后保存，也可先手动测试。新建与导入连接默认只读。右上角可即时选择中文 / English，偏好重启后保留。

SSH 使用现有账户和 OpenSSH 私钥路径、密码或 SSH Agent。输入服务器上 Docker socket 的路径，默认 `/var/run/docker.sock`。服务器禁止 Unix 转发时会使用固定 Docker CLI 通道并分配额外 SSH 连接，回退模式上限为 48 个并发 HTTP 通道。远程管理不要求本机安装 Docker Desktop，也不需要开放 2375。账户必须有访问 Docker socket 的权限。

第一次遇到未知 SSH 指纹时，使用可信渠道核对；核对后勾选“已核对”并信任重试。已知指纹发生变化时程序阻断，不会自动接受。应用信任记录位于自己的数据目录，同时读取现有 `~/.ssh/known_hosts`。

本地 Socket 示例：macOS Docker Desktop 常见 `unix:///Users/用户名/.docker/run/docker.sock`；OrbStack / Colima 可通过“导入连接”发现。Linux 可用 `unix:///var/run/docker.sock` 或实际 rootless socket。Windows 常用 `npipe:////./pipe/docker_engine`，需在 Windows 系统实际验收。

TCP 使用 `https://主机:端口`，配置 CA 与需要的客户端证书、私钥。证书和主机名始终校验。

## API 版本

优先保留“自动协商”。本版 SDK 支持 API 1.40–1.56；服务端最高 1.43 时可以选用 1.43。需要排障时可按连接指定版本，超出双方范围会拒绝。设置不会修改系统 `DOCKER_API_VERSION` 或其他 Docker context。

## 日常操作

主机下按 Compose project / service 标签分组。点击项目可看合并日志，点击容器进入该对象标签；上方操作与下方日志 / Inspect / 资源 / 终端跟随选中的容器。项目日志按钮返回整个项目的日志范围。Cmd/Ctrl+K 搜索已连接主机的容器。

日志支持关键字、级别、起始时间、跟随和换行；“暂停跟随”仍接收日志。清空只影响本地缓冲。导出保存当前过滤后的日志；日志内容可能包含业务敏感信息。缓冲最多保留 50,000 行并按约 32 MiB 限制淘汰旧条目。

需操作时，在连接设置关闭“只读”，点击“应用”或“保存”即可生效；名称、环境、工作空间及只读模式的修改无需重新测试。主机、认证、连接参数或 API 变化时，应用或保存会先自动测试，失败则保留草稿并提示错误。启动 / 停止 / 重启会先显示主机和具体目标；确认后逐个执行，查看每项成功、失败或结果未知。未知结果应刷新确认后再决定是否重试。容器运行中不等于业务健康。

终端只允许对选中的运行中容器主动打开 `/bin/sh` 或 `/bin/bash`。切换对象、关闭面板或退出程序会回收流。终端命令具有远端账户的实际权限。

## Compose 部署

通过标签发现项目后，先关联执行主机上的工作目录和原始 Compose 文件，可指定多个文件、env 文件与 profiles。SSH 项目在远端运行已安装的 `docker compose`；本地端点使用本机 Docker CLI。仅通过 TLS 连接的远端没有文件执行通道，部署操作会拒绝。

执行前解析配置，预览后再次解析并比较摘要；配置变化时要求重新预览。每次调用明确指定同一 Docker endpoint 与协商后的 API，隔离外部 Docker context。Pull / Up / Recreate / Down 都有操作记录；Down 不加 `--volumes`。

首版不显示完整 Compose 配置差异，也不代替发布系统的健康探测、依赖编排回滚和审批流程。

## 迁移与保存

“导入连接”将所选配置保存到当前工作空间，提供 SSH config 与 Docker contexts 发现预览、选择和去重；也可导入本应用导出的 JSON。不会改变系统 current context。复杂 ProxyCommand、多级 ProxyJump 和 PPK 请先转为受支持配置。

“导出连接”仅导出当前工作空间的连接元数据及私钥 / 证书路径，不含口令和私钥内容。IDEA 专有连接与 Password Safe 不自动读取，可按截图填写，或从 SSH config / Docker contexts 导入。

选择“记住凭据”时使用 macOS Keychain、Windows Credential Manager、Linux Secret Service；否则仅保存在核心进程内存。Linux 凭据服务不可用时可使用会话凭据。修改目标地址后不会自动沿用旧目标的密码。

应用数据目录由系统决定，macOS 为 `~/Library/Application Support/com.dockerworkbench.desktop/`。其中 SQLite 存放工作空间、连接归属、当前空间、布局和最近 500 条操作记录，日志默认不写入数据库。

## 软件更新

0.1.4 起，右下角“软件更新”可手动检查新版本。正式构建启动后默认自动检查，可在该窗口关闭“启动时检查更新”；偏好保存到本机 SQLite。后台检查发现新版本时入口会提示，不会自动安装。网络异常不影响 Docker 连接。

确认版本说明后点击“下载并安装”，应用显示下载进度并验证签名；失败时请重新检查后重试。macOS / Linux 安装完成后点击“立即重启”；Windows 安装会自动退出应用。重启前会关闭 Go 核心和当前连接、日志与终端。请先保存配置并完成容器或 Compose 操作。Linux 自动更新适用于 AppImage，deb 用户通过新安装包升级。

0.1.3 及更早的本地构建没有更新入口，首次升级需手动安装 GitHub Release 的安装包。更新包签名独立于 Apple Developer ID / Windows Authenticode 签名；现有发行的系统签名状态见 README。

## 单实例运行

0.1.5 起，同一应用身份只允许运行一个实例。再次启动时，新进程会退出，原窗口会从最小化恢复并获得焦点，不会重复启动 Go 核心。退出后可以正常重新启动，软件更新重启时会释放实例锁。

macOS 启动器中的多个图标通常来自磁盘上保留的多份 `.app`，不等于运行中的实例数量。日常使用请将一个正式版本放在“应用程序”目录，历史安装包优先保留为 DMG 或压缩包，避免解压后的历史应用被启动器重复收录。

更新请求遵循操作系统代理及标准代理环境变量，TLS 和更新签名校验始终保留。需要代理的网络，请先在系统设置中配置代理。
